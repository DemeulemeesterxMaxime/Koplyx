# Leçons actives

[2026-09-13] | Les scripts Python lancés depuis `tests/` ne résolvent pas automatiquement le paquet à la racine. | Ajouter explicitement la racine du dépôt à `sys.path` dans les scripts de test autonomes.
[2026-09-13] | Sous Xvfb, le démarrage complet de GTK peut être bloqué par les portails du conteneur avant d'atteindre le code applicatif. | Tester l'indicateur D-Bus de façon isolée et compléter par un contrôle sur une session de bureau réelle.
[2026-09-13] | Le lanceur Snap 0.3.0 utilisait `SNAPCRAFT_ARCH_TRIPLET`, variable présente au build mais absente au runtime, et quittait avant le démarrage de l'application. | Ne jamais exposer une variable `SNAPCRAFT_*` dans un script exécuté par Snap et vérifier le lanceur dans le smoke test sans cette variable.
[2026-09-13] | Le filtre `stage` du part Snap excluait les dépendances déclarées dans `stage-packages`, dont Python et ses modules. | Ne jamais restreindre `stage` sans vérifier que chaque dépendance runtime est incluse dans le Snap produit.
[2026-09-13] | Les noms de service D-Bus qu'un Snap possède doivent être déclarés comme des `slots`, les `plugs` étant réservés aux services consommés. | Pour une application GTK Snap, ne jamais rendre l'ouverture de la fenêtre dépendante d'une autorisation de nom D-Bus externe.
[2026-09-18] | Le script de smoke test utilisait `rg`, absent de l'image GitHub Actions. | Dans les scripts de packaging, utiliser les utilitaires POSIX installés par défaut ou déclarer explicitement chaque dépendance CI.
[2026-09-22] | Un profil local contenait des entrées chiffrées avec une clé différente et faisait échouer le rendu sur `InvalidToken`. | Une entrée illisible ne doit pas interrompre l'interface : gérer l'échec de déchiffrement et permettre sa suppression.
[2026-09-22] | Un test GTK lancé sur le bus de session partagé entrait en collision avec une instance Koplyx déjà enregistrée. | Isoler les tests GTK avec `dbus-run-session` pour éviter les collisions d'identifiant d'application et les faux segfaults.
[2026-09-22] | La boîte « connexion à distance » a été attribuée à tort à une ancienne fenêtre XWayland, sans preuve. Les journaux montrent des demandes du portail liées à XTEST. | Vérifier les journaux et le texte réellement collé ; sous Wayland, gérer une session clavier autorisée du portail, sans utiliser le succès de `xdotool` comme preuve de collage.
[2026-09-22] | Le raccourci lançait le Snap pendant le test d'une instance source, et le CSS global déformait les contrôles de fenêtre. | Vérifier le chemin et le profil du processus testé ; limiter le CSS des boutons au contenu applicatif.
[2026-09-22] | Le test Wayland dépendait implicitement de la présence locale de `xdotool`, ce qui rendait le résultat non déterministe après l'ajout des replis directs. | Simuler explicitement la liste des outils disponibles dans les tests de restauration Wayland.
[2026-09-22] | `restore_item` arrêtait le parcours lorsque l'indicateur système était indisponible, donc le presse-papiers était restauré sans tentative de Ctrl+V. | Masquer temporairement la fenêtre pour le collage même sans indicateur, puis réafficher Koplyx après le résultat.
[2026-09-22] | Le texte de test de l'assistant est exclu de l'historique, mais cette règle n'était pas assez visible pendant le parcours manuel. | Annoncer explicitement que le test ne crée aucune entrée et demander une copie réelle pour valider l'historique.
[2026-09-22] | `launch_xwayland_backend` existait mais n'était relié à aucune étape de l'assistant, et l'absence de session Xorg était silencieuse. | Relier la relance XWayland au parcours et afficher le diagnostic Xorg même lorsque l'option de redémarrage est indisponible.
[2026-09-23] | L'assistant masquait sa fenêtre et la fenêtre principale pendant le test, ce qui pouvait terminer la boucle Gtk avant le rappel de résultat. | Maintenir `Gtk.Application` pendant tout test sans fenêtre visible, puis libérer l'application dès que l'assistant est réaffiché.
[2026-09-23] | Le test de repli remettait l'ancien texte dans le presse-papiers avant que l'utilisateur puisse essayer Ctrl+V. | Garder le marqueur actif jusqu'à la réponse dans le mode manuel et restaurer le texte précédent lors de la confirmation ou de la fermeture.
[2026-09-23] | Un test UI supposait que la machine disposait d'une session graphique et d'un outil d'injection précis, ce qui échouait sur le runner GitHub propre. | Simuler la liste des backends disponibles dans les tests UI et réserver les dépendances système aux validations d'intégration.
[2026-09-23] | Le bouton « Tester le presse-papiers » enregistrait directement le mode sans lancer l'essai actif. | Garder tous les boutons de test dans le même flux d'exécution et ne mémoriser le backend qu'après le retour de résultat.
[2026-09-23] | La sonde navigateur recevait un retour positif de ydotool sans retrouver le marqueur dans le champ cible. | Vérifier le texte réellement inséré après le délai de traitement du presse-papiers; un code retour positif ne suffit pas.
[2026-09-24] | Une fenêtre GTK Wayland lancée par une sonde n'obtenait pas le focus avec `present()` et `grab_focus()`. | Ne jamais injecter une touche avant de vérifier le focus et le texte dans un champ cible actif.
[2026-09-24] | Un test GTK instancie `CryptoBox` et peut contacter le trousseau GNOME réel, ce qui bloque sous Xvfb. | Isoler les tests en simulant `load_secret_service_key` afin qu'ils restent confinés à leur profil temporaire.
